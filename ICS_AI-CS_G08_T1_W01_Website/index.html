Learning objectives and success criteria

  • Generate at least two focused questions about how AI systems process inputs, generate outputs, and can be evaluated
  • Co-construct the unit success criteria and the class responsible-use norms for AI tools.

I can…

  • I can ask at least two good questions about how AI turns an input into an output and how we judge that output.
  • I can sort examples that relate to evaluating and improving AI models, and say why.
  • I can help write our unit success criteria and our safe, responsible-use rules for AI tools.

Explanation and examples

An AI system takes an input, runs a process built on a model trained from many examples, and returns an output. This unit adds a question on top of that workflow: is the output any good, and how do we know? To answer it we set clear performance criteria - measures such as accuracy, usefulness and fairness that fit the task - and we judge outputs against them rather than by first impression. Improving a model then means changing something in the input or the process so more outputs meet the criteria. This launch lesson surfaces what students know and frames good questions; it does not build or evaluate a model yet. Keep all tool use teacher-operated, account-free and free of personal data, and verify every output before trusting it. Anticipated misconceptions Misconception How to address it A better-looking output is always the better output. Put a tidy but wrong output next to a plain but correct one and check both against the task; agree that 'good' means meeting the criteria, not looking polished. Improving a model just means asking the AI to try again. Show that improvement is a deliberate change to the input or the process, then re-testing against the same criteria - not simply hoping for a nicer result. If the AI is confident, the output must be right. Display a curated output that is confidently wrong, check it against a trusted source, and establish verify-before-trust as a class norm.
