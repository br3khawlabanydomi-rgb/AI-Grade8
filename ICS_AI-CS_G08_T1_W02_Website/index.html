Explanation and examples

An AI system is a pipeline. It receives an input (data such as text, an image or a sensor reading), passes it through a proce ss - a trained model that applies patterns learned from many examples - and returns an output (a prediction, a label or generated content). Understanding the system means naming each stage and reasoning about how one becomes the next: the model does not grasp meaning, it maps inputs to statistically likely outputs. For Grade 8 this matters because the unit's goal is to evaluate and improve models. You cannot judge whether an output is good, or improve it, until you can see the stages it came from and identify where the result was shaped - by the input given, the data the model learned from, or the way the system was designed. Training, inference and evaluation (teacher background) Machine learning (ML) means building a model by learning patterns from a dataset instead of writing fixed rules by hand. The dataset splits into TRAINING DATA (the examples the model learns from) and TEST DATA (separate, new examples kept back to check it - never test on a training example). Three actions matter: TRAINING is teaching the model from the training data; INFERENCE is one forward run that turns a new input into an output; EVALUATION is measuring the outputs against your criteria using the test data. If you change the training examples and train again, the result is a NEW, retrained model - not the same one. Students train their first model, and meet these terms in practice, in today's Lab. Hands-on activity guide Overview: Students investigate three teacher-provided worked examples, map how each input becomes an output through a trained model, and explain the reasoning to a partner. Grouping / timing: Pairs for the investigate and explain; whole class for the debrief. Tool: A teacher-operated board demo with a curated, pre-generated set of example inputs and outputs - no accounts and no live typing by students - so the class studies safe, prepared results and no personal data is ever entered. Describe what the model does to it and write it next to Process. 4. Write down the output - the exact result that came out. 5. Explain to your partner how the input became the output, in order. 6. Check one output against the task and a trusted source - does it really answer it? Unplugged fallback: Simulated-AI cards: a 'model' envelope holds a fixed rule matched to example cards. A student posts an input card in and the envelope returns the matching output card - the same pipeline with no device and no accounts.
